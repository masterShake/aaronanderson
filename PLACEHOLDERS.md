## Deployment settings

### Deployment

- [ ] Vercel sets VERCEL_ENV itself. Set it locally only to test the production look.
- [ ] Turn on Skew Protection in the Vercel project (Settings, Advanced) so old tabs keep working after a deploy.
- [ ] Never Instant-Rollback to a build made before the HOLDs were filled; promote a fresh build instead.
- `VERCEL_ENV` (optional): production | preview | development
- `SHOW_HOLDS` (optional): 1 = HOLD clouds visible; 0 = production fallbacks. Default: 0 only when VERCEL_ENV=production
- `STRICT_HOLDS` (optional): set in Vercel's Production env at launch: the build fails while essential HOLDs or pending CONFIRMs remain
- `CSP_MODE` (optional): report = Content-Security-Policy-Report-Only; default enforce

### Contact form (server only)

- [ ] Verify the sending domain in Resend and add its DNS records (SPF, DKIM, return path) at the domain host.
- `RESEND_API_KEY`: "Sending access" key restricted to the verified domain. Unset in dev: email is logged, not sent
- `CONTACT_TO_EMAIL`: comma-separated inbox(es) that receive enquiries
- `CONTACT_FROM_EMAIL`: e.g. Actual Engineer <contact@mail.actualengineer.com> (verified Resend domain)
- `FORM_TOKEN_SECRET`: required in production; openssl rand -base64 32. Without it every form token counts as missing

### Booking

- [ ] Create the Cal.com event and paste its link into src/content/site.ts (site.scheduler.url). There is no scheduler env var.

### Cloudflare Turnstile (optional; set both or neither)

- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (optional): tests use 1x00000000000000000000AA
- `TURNSTILE_SECRET_KEY` (optional): tests use 1x0000000000000000000000000000000AA

### Rate limiting (optional; falls back to an in-memory limit per instance)

- `UPSTASH_REDIS_REST_URL` (optional): KV_REST_API_URL is accepted as a fallback
- `UPSTASH_REDIS_REST_TOKEN` (optional): KV_REST_API_TOKEN is accepted as a fallback

### Local tooling (never set on Vercel)

- `PORT` (optional): next start and Playwright; each worktree reads its own from .lane.env
- `DEV_PORT` (optional): next dev; read from .lane.env
- `LH_RUNS` (optional): Lighthouse runs per route
